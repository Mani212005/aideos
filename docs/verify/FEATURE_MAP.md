**Property-based testing status**: aideos has **no property-based testing library** in `package.json`, `editor/package.json`, or `native/Cargo.toml`, and none is needed yet: the pure invariants tested so far are covered by a zero-dependency seeded runner, `backend/testSupport/propertyTest.ts` (mulberry32, `forAll`, failing seed and input in the message, `AIDEOS_PROPERTY_SEED=<n>` replays one case). It is used by `backend/timeFrameArithmetic.property.test.ts` (shot timeline tiling and half-frame drift bound, millisecond grid, delivered length with the end card, caption placement clamping), `backend/timeline/layerIds.property.test.ts` (layer and clip id uniqueness and references over random edit sequences), `backend/schemaRoundTrip.property.test.ts` (generated film JSON round trips through `parseFilm`) and `backend/audio.test.ts` (retime cache key: same inputs give the same key, different sources differ, two speeds share a key exactly when they share an ffmpeg atempo filter). Older invariant and randomized tests use handwritten deterministic loops (for example `backend/journeys/character_retarget.journey.ts` over random proportions, `backend/editPlanner/ai_edit_invariants.test.ts`, `backend/editPlanner/phase3_invariants.test.ts`, and `backend/pipeline/agent_director_invariants.test.ts`). Recommended libraries if adopting one later (do not add without explicit approval): `fast-check` for TypeScript/Node and `proptest` for Rust.

**Expect testing status**: `backend/testSupport/expectFile.ts` compares real captured output with reviewed files under `test_fixtures/expect/` (`AIDEOS_UPDATE_EXPECT=1` rewrites them, review the git diff before committing). Covered: Render IR (`backend/renderIr/emit.expect.test.ts`, long and reel), film JSON as written by the film store (`backend/pipeline/filmJson.expect.test.ts`), shot timeline, delivered length and caption placement results (`backend/timelineResults.expect.test.ts`), the full review report with encoder-sensitive measurements normalized (`backend/review/review.test.ts`), the stable CLI help text for `aideos-backend` and `review` (`backend/cli.expect.test.ts`), model reply parsing (`backend/modelReply.expect.test.ts`), Jev request and reply parsing (`backend/jev.expect.test.ts`), Gemini review prompt and reply parsing (`backend/geminiReview/geminiReview.expect.test.ts`), and media facts from the shared ffprobe wrapper (`backend/media/probe.expect.test.ts`).

## Protected test suites (never loosen)

Per the owner test policy (see [.agents/skills/verify/references/test-policy.md](../../.agents/skills/verify/references/test-policy.md)), never loosen an assertion, tolerance, timeout, or golden in these suites to make a run pass. Weak tests outside these protected guarantees may be removed (at roughly 60-70% confidence) with a one-line reason in the PR.

## Aideos verification commands and independent review

- **Full unit & fixture job**: `bun run ci -- unit`
- **Targeted journey**: `node --import tsx --import ./backend/testSupport/fixtureVideosDir.ts --test --test-concurrency=1 backend/journeys/<name>.journey.ts`
- **Native Rust tests**: `cargo test --locked --manifest-path native/Cargo.toml`
- **Legacy goldens (Linux)**: `bun run ci -- legacy`
- **Independent code/PR review pipeline**: `no-mistakes` (separate reviewer models inspect the diff and lint/test results before PR merge)
- **Independent video review pipeline (for film packages)**: `aideos review <slug>` + `aideos all-check <slug>` (Gemini 3.8 Flash via `agy`)
