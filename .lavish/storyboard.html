8.4 · REUSE ACROSS REQUESTS

Prefix caching. Don't re-cook the starter you already prepped.

Two requests to the same model sharing an identical prefix (a long system prompt, the head of a conversation) can reuse the computed cache instead of rebuilding it.

THE FINE PRINT

Same model. Exact token-for-token prefix match.

Change anything upstream, including which model you are on, and the match breaks, the cache is invalidated, and you are back to a full prefill. That is the mechanism behind the behaviour you noticed.

WHY SPECULATIVE DECODING WORKS

It shares tokens, not tensors.

A small draft model proposes ahead; the big model verifies in one batched pass. Each keeps its own cache in its own format. Plain token IDs carry no model-specific internal meaning, so they are safe to pass between architectures.
